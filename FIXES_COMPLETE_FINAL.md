## 💡 How It Works Now

### ID Generation
All IDs are now generated by the database with collision detection:
- **Patient ID:** P000001000, P000001001, etc.
- **UHID:** UHID2025001000, UHID2025001001, etc.
- **Drug Code:** DRG-20251201-1000, DRG-20251201-1001, etc.
- **Prescription:** RX-20251201-1000, RX-20251201-1001, etc.
- **Lab Order:** LAB-20251201-1000, LAB-20251201-1001, etc.
- **Invoice:** INV-20251201-1000, INV-20251201-1001, etc.
- **Radiology:** RAD-20251201-1000, RAD-20251201-1001, etc.

### API Configuration
All API calls now use `API_CONFIG`:
```javascript
// Automatically uses correct URL based on environment
fetch(`${API_CONFIG.endpoints.patients}`, {
  headers: API_CONFIG.getAuthHeaders()
});
```

**Development:** Uses `http://localhost:3001`  
**Production:** Uses environment variable  
**Docker:** Uses container networking

## 🆘 Troubleshooting

### If you get "Cannot connect to server"
1. Check containers are running: `docker-compose ps`
2. Check backend logs: `docker logs medimesh-patient-api`
3. Verify API_CONFIG is imported in the file

### If you get "Permission denied" errors
Already fixed! But if it happens:
```bash
docker exec -it medimesh-postgres psql -U postgres -d medimesh -c "GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO medimesh_user;"
```

### If you get "Module not found: API_CONFIG"
Check the import path is correct:
```javascript
import API_CONFIG from '../config/api';  // for pages
import API_CONFIG from '../../config/api';  // for components
```
